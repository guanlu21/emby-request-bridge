# Emby求片（emby-request-bridge）

独立的求片站（不依赖 Seerr，内存占用小）：
Emby 用户登录 → 搜 TMDB → 选片/选季 → 自动搜资源（PanSou 的 115 分享 + CloudSaver 的 115 分享 + 纸鸢磁力的磁力）→ 115 转存/离线 → LitePan 整理并生成 strm → 通知 Emby 刷新。

## 夸克网盘（只转存分享链接）
- 在「设置 → 夸克网盘」填 Cookie（浏览器登录 pan.quark.cn，开发者工具里复制请求的 Cookie），再选「夸克下载目录」和「夸克影视根目录」，点「测试夸克连接」。**不设这三项就不会使用夸克**
- 夸克**没有磁力离线下载**，只能转存分享链接：PanSou、CloudSaver、电影港搜到的夸克链接，会转存到夸克下载目录的临时文件夹 → 过滤视频 → 按分类移到夸克影视根目录（目录结构、命名格式、删除/替换都和 115 一样）
- 115 和夸克可以同时用：每个资源按它所属的网盘走对应流程；某个网盘的目录不通，不影响另一个。「设置 → 选源规则 → 优先使用的网盘」可以选优先哪个（只是排序，另一个照样补缺）
- LitePan 联动：夸克入库的联动来源会带「夸克-」，如 `Emby求片-夸克-电影-国产`，「联动来源清单」会把 115 和夸克的来源、扫描目录都列出来；要在 LitePan 里为夸克网盘另建 STRM 任务和联动（LitePan 支持夸克）
- 夸克接口（转存、建目录、列目录、移动、改名、删除）是按社区常见用法写的，**没有用真实账号验证过**；失败时报错会写出夸克返回的内容，Cookie 失效也会提示

## 电影港（dyg7.com）和海搜（haisou.cc）
- **电影港**已接入（设置 → 资源搜索，默认启用，地址可改）：搜到影片页后，从页面里取磁力（带「国语中字无水印、全集打包、1080p」这类标签和文件大小）和夸克/115 分享链接；页面上的「年代」会补进标题参与年份判断。迅雷、百度的链接不要。电视剧里只有部分集的磁力（如 01-08）会排在整包后面
  - 影片页的结构我对照真实页面核对过；**站内搜索**是按帝国 CMS 的标准写法（POST /e/search/index.php，依次试几个表名），没法确认这个站的表名，设置页「测试电影港」会显示每次尝试的结果
- **海搜**：已按你抓到的请求（`POST /api/v2/shares/search`，请求体含 query、filters.platforms、pagination；`POST /api/v2/shares/{id}/fetch`，请求体 `{}`）做成实验版，默认关闭。**但网页版每个请求都带一个 `x-hs-client-context` 头（每次不同的一长串，像页面脚本生成的签名）**，本服务不模拟它、也不使用浏览器的会话 Cookie，发的是普通请求；站点如果因此拒绝，海搜就用不了。「测试海搜」会显示实际返回。夸克资源可以走 PanSou、CloudSaver、电影港

## 页面与手机适配
- 电脑：顶部导航；设置页左侧是分类导航（连接：Emby / 115 网盘 / 资源搜索 / 代理与 TMDB；入库：入库分类 / 命名格式 / LitePan 联动；规则：选源规则 / 关键词筛选 / 审批与限额；安全：API 令牌），右侧一次只显示一组，各组自带对应的测试按钮和结果；「保存设置」固定在底部
- 手机：主导航移到底部（拇指够得着），设置分类变成顶部可横向滑动的标签，请求列表和管理列表自动变成卡片，海报两列显示，弹窗占满宽度，输入框和按钮放大到好点的尺寸（也避免 iPhone 自动缩放）
- 管理页多了「全选/取消」按钮（手机上没有表头的全选框）

## 首次使用
1. 只需要把容器的 `/data` 挂载到 NAS 上的可写目录，启动后打开站点（容器端口 8686）
2. 登录页会多一个「Emby 地址」输入框：填局域网地址（如 `http://192.168.1.10:8096`），用 **Emby 管理员账号**登录。这个账号自动成为本站管理员，并自动为本站创建 Emby API 密钥（失败的话在设置里手动填）
3. 进「设置」，把下面这些配置在网页里填好（都不用再碰环境变量）：
   - **115 网盘**：填 Cookie（或填 AppID 后扫码授权）→ 点「测试 115 连接」；电影/剧集/暂存三个目录用「选择」按钮浏览 115 目录挑选（选之前会自动保存当前设置）
   - **资源搜索**：PanSou 地址；CloudSaver 地址、用户名、密码；纸鸢磁力的 MCP 地址和 Token（都可选，见下面）
   - **LitePan 联动**：LitePan 地址和 API 秘钥（见下面「对接 LitePan」），填完点「测试 LitePan」
   - **代理与 TMDB**：TMDB Key、语言、主机名、代理（与 LitePan 的设置项一致，有「测试连通性」）
   - **审批与限额**、**选源规则**、**管理员名单**
4. 之后 Emby 用户用自己的 Emby 账号密码登录，搜索、求片；管理员在「管理」页批量通过

## 日常使用
- 搜索影片或剧集名称（走 TMDB），点「求片」；剧集可选要哪几季
- 普通用户的请求默认进「待审批」，管理员勾选 → **批量通过**；管理员自己求片直接处理；「设置 → 审批」可改成全部自动处理
- 「我的请求」看自己的进度；管理页可按用户/状态筛选，批量通过/拒绝/重试/删除，失败的"批量重试"会继续换下一个候选
- 管理员名单在设置里可增减（逗号分隔的 Emby 用户名）

## 115 登录方式（二选一，或都配）
- **只填 Cookie（最简单）**：没有 AppID 也能用，建目录、选目录、转存分享链接、磁力离线都走 Cookie。缺点是 Cookie 会失效，失效后到 115 网页重新复制，粘贴到设置里保存即可
- **115 开放平台扫码授权（更稳）**：有 AppID 时在设置里填好并点「扫码授权」，令牌到期前自动续期。授权后文件操作和磁力离线优先走开放平台；但开放平台没有"转存分享链接"接口，要转存 PanSou 搜到的分享链接，仍需额外填 Cookie
- 两个都没配时，选目录和求片会提示"还没有登录 115"
- 同一个开放平台应用，一个账号最多保留两个有效授权，第三次授权会让最早的失效——所以建议给本服务单独申请 AppID，别和 LitePan 共用
- 设置页的「测试 115 连接」会显示当前走的是哪种方式，并列出根目录文件夹数

## 入库流程：云下载 → 过滤 → 分类移动 → 改名 → STRM → Emby
1. 磁力提交到 115 的「云下载」目录（在「设置 → 115 网盘 → 下载目录」选 115 的「云下载」文件夹；每个请求在里面建一个临时子文件夹，用完即删）
2. 下载完成后**只保留视频文件**（mkv/mp4/ts/m2ts/avi/mov/wmv/flv/rmvb/webm），**小于 100MB 的删除**（样片、花絮；阈值在「设置 → 入库分类」里改）；带水印名称的文件也不要；电影的分享/磁力里有多个版本时只留一个（优先 1080p、1–3GB）
3. 按 TMDB 信息**自动分类**，移进「影视根目录」下对应子目录（没有就自动创建）：
   - 电影 → `电影/国产|港台|日韩|欧美/片名 (年份)/`
   - 电视剧 → `电视剧/国产剧|港台剧|日韩剧|欧美剧/剧名 (年份)/Season 01/`
   - 动画（日本、国产、韩国的动画剧集；日本动画电影）→ `动漫/…`；欧美动画电影、动画剧仍按地区放电影/电视剧
   - 真人秀、脱口秀 → `综艺/…`；纪录片 → `纪录片/…`
   - 地区判断：日语、韩语 → 日韩；粤语，或中文片的制作地在香港/台湾 → 港台；中文片在大陆（含大陆香港合拍）→ 国产；其它按第一个制作国家，默认欧美。例如《流浪地球》→ `影视/电影/国产/流浪地球 (2019)/`
4. 按 Emby 习惯**改名**（尽力而为，失败只记日志保留原名）：电影 `片名 (年份).mkv`；电视剧 `剧名 (年份) - S01E01.mkv`，集数从文件名里的 E05、第5集、[05]、" - 05 " 等写法识别，认不出的保留原名
5. 通知 LitePan 联动（见下面），由它刷新目录 → 生成 STRM → Emby 扫库

### LitePan 联动怎么配（整理和分类已经由本服务做完，联动里不需要「整理」了）
自动联动里：触发 = 收到通知 `download_completed`（来源与本站「联动来源」一致）→ 动作依次：**刷新目录** → **执行 STRM 任务**（该 STRM 任务的源目录选「影视根目录」）→ **Emby/JF 扫库**（可再加「生成本地 STRM 元数据」）。把原来的「整理任务」那一步删掉。

## 搜不到资源时怎么查、怎么加搜索源
- 管理页每条请求的「日志」会写：各搜索源有没有配置/出错、搜到多少条、**按原因统计被过滤掉多少**（标题不匹配、年份不符、带水印、体积不在范围……）以及几个被过滤的示例标题，照着调
- 标题匹配比较宽松：年份允许 ±1、没写年份也行、英文名词序/标点不同、忽略副标题；剧集支持「全40集」「E01-E40」这类整季写法（单季剧可以不写 S01）；每个片名会用多种关键词各搜一遍
- 管理页失败的请求有「手动资源」按钮：直接粘贴一个 115 分享链接或磁力链接，跳过搜索，仍会按规则筛选视频文件

### 纸鸢磁力：为什么「磁力帝」「BitSearch」搜得到、这里搜不到
纸鸢磁力的设计是：**除「综合匹配」「快速搜索」（服务器上的本地库）外，其它引擎（磁力帝、BitSearch…）是在你的浏览器里按规则去请求各个磁力站的**，数据不经过它的服务器。它的 MCP 接口只有服务器那一头，所以 `magnet_search` 只能搜本地库，拿不到磁力帝的结果——这也是「鬼片王之再现凶榜」在网页里能搜到、求片里搜不到的原因。
要让求片直接搜磁力帝/BitSearch，只能由本服务自己去请求这些站点：需要你把这两个引擎的**规则**（纸鸢磁力里导出/复制的 JSON，里面有搜索网址、请求方式、怎么从页面里取标题/磁力/大小）发给我，我照着做成搜索源。这些站点要从 NAS 上能访问到（你的浏览器走了代理的话，本服务也要配代理）。

### 纸鸢磁力（国内磁力站聚合）
- 「排除的搜索引擎」默认 `综合匹配,快速搜索`：返回结果里带有引擎/来源信息时，这些引擎的结果会被丢弃。**MCP 的 magnet_search 工具说明是「仅本地库」，我不确定它的返回里有没有引擎信息、能不能指定引擎**——点「测试纸鸢磁力」会显示工具的参数、结果里出现的引擎名和原始返回，据此再调整；如果它只返回本地库，需要抓网页版搜索「磁力帝」时的请求才能直接调用
纸鸢磁力（magnet.kiteyuan.info）把多个国内磁力站按规则聚合，并提供 MCP 接口。在「设置 → 资源搜索」填：
- **MCP 地址**：以纸鸢磁力「MCP」页面里客户端配置的 `url` 为准（页面地址 `.../mcp` 不一定就是接口地址）
- **MCP Token**：在该页面生成（`mcp__` 开头）
填完点「测试纸鸢磁力」：会列出服务端提供的工具，并试搜一次看能不能解析出结果。你常用的其他磁力站，建议在纸鸢磁力里按它的自定义规则添加，这边自动就能搜到。
- 结果格式没有官方文档，解析做得比较宽松（JSON、文本都尝试）；如果测试显示搜到 0 条或标题乱，把测试提示发给我调整

## 磁力离线下载
- 磁力链接通过 115 的「云下载」接口提交到暂存目录，完成后（目录里出现文件）按规则过滤、移到正式目录
- Cookie 方式用的是 p115client 库；这个库的方法名随版本改过（`offline_add_url` → `clouddownload_task_add_url`），程序会按新旧名字依次查找；找不到时报错会列出库里实际有的相关方法名，并**立即终止**，不会把候选资源挨个烧掉
- 开放平台方式的接口（建目录、列目录、移动、删除、添加/查询云下载任务）已对照 115 官方开放平台文档核对过
- 「设置 → 选源规则」里的「单个资源离线等待上限」默认 600 秒：一直下不完的死种，到时间就换下一个
- LitePan 自带的离线下载和分享转存目前没有公开的外部接口（文档里对外的只有自动联动的第三方通知），所以本服务不通过 LitePan 下载；如果想走 LitePan，需要提供它网页端提交离线任务时的请求（见下方 FAQ）

## 115 报「父目录不存在」(errno 20009)
- 含义：设置里选的暂存/电影/剧集目录，115 找不到。现在每次求片开始前会先检查这几个目录，不通就直接失败并说明是哪个目录，不会再把候选资源挨个试一遍
- 0.x 版本里有个已修复的问题：115 目录 ID 有 19 位，超出浏览器 JSON 数字精度，选出来的 ID 会被截成错误的数字。升级后**需要把三个目录重新选一遍**，再点「测试 115 连接」
- 管理页的「批量重试」是接着往下试没试过的资源，「重新搜索」会清空已试记录从头来

## 人物搜索与删除网盘文件
- **人物搜索**：搜演员/导演的名字，结果上方会出现「相关人物」，点开是他参演、导演的全部影视作品（从新到旧，去掉脱口秀、新闻和「本人」客串），每部都带「已入库/求片」状态，点作品直接求片
- **批量删除可以同时删网盘文件**：管理页勾选后点「批量删除」，弹窗里勾选「同时删除 115 网盘里已入库的文件」。只删这些请求入库的视频文件（记录在案的），因此变空的片名/季文件夹一并清掉，分类目录和别的内容不动；先删网盘、成功后才删记录，网盘出错会停下、记录保留，可以重试
- 注意：LitePan 生成的 STRM 文件不会被删，要在 LitePan 里另行清理（否则 Emby 里会留下播放不了的条目）

## 磁力站：磁力帝、BitSearch 等（按纸鸢磁力的规则直接搜）
- 纸鸢磁力的这类引擎是在浏览器里按「规则」请求各个磁力站的，它的 MCP 接口只有服务器本地库，所以求片里用 MCP 搜不到磁力帝。现在本服务**直接解释同一份规则文件**，自己去请求这些站：自带一份规则（来自你导出的 `exmple_rule_20260803.json`，**已去掉 8 个成人类引擎**，成人类（porn 标签）引擎一律不使用），默认启用 **磁力帝、BitSearch**
- 设置 → 资源搜索：「磁力站」填要用的引擎名（逗号分隔；可用的名字点「测试磁力站」查看，还有磁力蜘蛛、BTShow、磁力口袋、Nyaa、Mikan、1337x 等）；「磁力站走代理」开启后用「代理与 TMDB」里配置的代理（这些站常要代理，没配就是直连）
- 想用你自己导出的最新规则：放到数据目录 `/data/rules.json`，同名引擎以它为准，没有的引擎追加
- 支持的规则：GET/POST、URL 里的 `%SearchKey% %Page% %Offset%`、JSON 请求体、HTML（CSS 选择器）和 JSON（点号路径）解析、`%btih%`/`%value%` 模板、列表里没有磁力时按 `nextStep` 点进详情页取。**只有标题完整包含片名的条目才会去取详情页**，每个引擎每页最多取 6 个
- 搜到的结果和其它来源一样走名称/年份/体积/关键词筛选；搜索深度越深，翻的页数越多（1/2/3 页）。《鬼片王之再现凶榜》这类在磁力帝才有的片，现在能搜到（447MB 的那条会被「电影最小 500MB」挡掉，要的话调低「单文件最小」）
- 请求到的页面结构变了、站点要验证码/被拦截时，设置页「测试磁力站」会显示每个引擎的 HTTP 状态和解析出多少条

## 下载成功但没入库、被删除了？
下载成功后还会检查：只留视频、每个视频要在「最小~最大」之间、电视剧要够「整季」。**没通过检查的内容会从下载目录删除**，所以会出现「115 离线记录成功、网盘里却没有视频」。现在：
- 请求日志会直接写原因，如「共 13 个文件：太小 12、非视频 1」（短剧一集只有几十 MB，会被「最小 100MB」挡掉，可在「入库分类 → 下载后保留的最小文件」调低）、「第 1 季只有 4 个视频，已播出约 10 集，至少要 5 个」
- **连载中的剧按已播出的集数算**（以前按 TMDB 的计划总集数，连载中的剧资源永远「不够整季」）
- 「整季最少集数占比」可调（默认 50%，0 = 不检查）
- 「保留没通过检查的下载」开启后不再删除，留在下载目录里改名为「未入库-…」，方便你自己看

## 管理页的日志不会再自动收起
管理页每 6 秒自动刷新一次，以前每次都会把列表整个重画，展开着的日志就被收回去了。现在：数据没变化时**不重绘**（你正在看的日志、选中的文字原样不动）；数据有变化需要重绘时，**展开/收起的状态也会记住**，只有你自己点才会收起。

## 时间显示
管理页和「我的请求」里每条请求显示三个时间：**求片**（提交时间）、**审批**（批准时间和批准人；不需要审批的显示「自动批准」；待审批显示「待审批」；已拒绝显示「已拒绝」）、**完成**（入库时间）。手机上是卡片里的一行。把已拒绝的重新放行也算批准，失败重试不改审批时间。

## 搜索稳定性（资源多的时候不再「全军覆没」）
- 以前所有关键词 × 所有来源同时发出，PanSou / CloudSaver 被压垮，整批请求一起超时，一条结果都没有。现在：**每个来源限制同时几个请求**（PanSou 3、CloudSaver 2、纸鸢 2、电影港和海搜各 1），其余排队；**每个请求有超时**，偶发错误自动重试一次；**整体有期限**（深度 1/2/3 分别 60/120/200 秒），到期限就用已经拿到的结果，不会因为个别请求卡住就一无所获
- 请求日志的「提示」里会写每个来源：几个请求成功、几个超时、几个出错（和错误类型）、得到多少条，哪个源有问题一目了然
- 「被过滤的资源」列表现在按**像不像**排序：差一点就匹配的（年份不符、体积不在范围、缺少关键词…）排最前，标题完全不沾边的排最后；想要的片被误过滤时更容易翻到

## 搜索匹配规则（名称完整匹配、年份辅助、多季优先、可深度搜索）
- **名称必须完整出现**在资源标题里，不拆词、不乱序、不去副标题，中文英文规则一样（只忽略大小写、空格和标点）：搜「唐人街探案」，标题里只有「唐人街」或「探案」的不算；「唐人街探案2」「唐人街探案 3」这种片名后面紧跟数字的当续集排除；TMDB 的中文名、英文名、原名三个名字任意一个完整出现即可
- **年份只是辅助条件**：同年、差一年、标题没写年份都收；年份差太多才丢。同年排在前面，没写年份的排后
- **电视剧一次求多季：一起搜索，优先用多季合集**，不是一季一季单独搜。合集（S01-S05、第1-5季、全8季、全集）下载一次，按文件夹/文件名里的季分到各自的 `Season NN` 目录；没覆盖到的季，再用其它资源补。合集里没求的季的文件会丢弃
- 标题没写季/年份也不一定被拒：第 1 季的「全26集」「26集」或干脆只有片名都收，下载后再核对文件；单集（S01E05、第5集）不收；第 2 季及以后、标题没写季，只收「全集/合集」，并且下载后必须能从文件名/文件夹名确认是这一季
- **搜索深度**（设置 → 选源规则）：1 普通 / 2 深入（默认）/ 3 最深。越深，用的关键词越多（加 1080p、国语、中字、全集、合集、第N季…）、纸鸢磁力返回条数越多（50/100/200）、PanSou 最深时不用缓存。某条请求搜不到想要的，在「候选/替换」里点「深度搜索」，用最深的再找一遍，只刷新候选，不下载
- **候选优先级**（设置 → 选源规则 → 候选优先级顺序）：电视剧先看覆盖了几季；然后按你排的顺序逐项比较：**中文名称（标题里有完整中文片名的最优先，其次含中文，全外文的最后）** → 年份吻合 → 画质（1080p 最优）→ 优先的网盘 → 优先关键词 → 体积合适 → 分享优先 → 做种数；最后看综合分。想「画质最优先」就把 `quality` 写到前面；以前保存过的顺序里没有 `chinese` 的，它会自动排第一
- **候选列表**每条显示满足了哪些要求（名称完整匹配、年份吻合、1080p、命中优先词、体积合适、覆盖第几季…）；另有「被过滤的资源」标签页，列出没通过筛选的和原因，可以**强制使用**；候选按 20 条一页，点「显示更多」

## 搜索与筛选
- **TMDB 搜索**：输入「片名 年份」（如 `流浪地球 2019`）可缩小范围；不带年份时取综合搜索前 3 页（最多 60 条）；带年份时电影、剧集各按年份搜前 2 页，搜不到再退回综合搜索并按年份过滤
- **CloudSaver**：从它搜到的 115 分享链接会和 PanSou 的结果一起排序（转存分享链接需要在设置里填 115 Cookie）。设置页有「测试 CloudSaver」；登录和搜索接口会依次试 `/api/user/login`、`/user/login` 和 `/api/search`、`/search`，失败时报错会写出每个路径返回了什么
- **关键词筛选**（设置 → 关键词筛选）：
  - 必须全部包含：逗号分隔，每项都要出现；一项里用 `|` 写同义词，如 `国语|国配|普通话, 中字|简中|中英字幕`
  - 至少包含其中一个、不能包含、优先包含（加分）
  - 同时检查资源标题和描述（CloudSaver 的正文里写了「国语中字」也算）；被它过滤掉的数量和原因会写进请求日志
- **候选资源与一键替换**（管理页，每条已完成/失败的请求有「候选/替换」按钮）：
  - 列出筛选后的候选（来源、分数、体积、已试过/当前使用）
  - 选一个「替换为此资源」：新资源**下载并通过筛选后**才会删除之前入库的文件再放新的；新资源失败则原文件保留、状态不变
  - 失败的请求可直接「使用此资源」；也可以「手动资源」粘贴链接

## 命名格式（设置 → 命名格式）
默认带 TMDB 编号，Emby 认文件夹名里的 `[tmdbid=编号]`：
- 电影文件夹 `流浪地球 (2019) [tmdbid=535167]`，文件 `流浪地球 (2019) [tmdbid=535167] - 1080p WEB-DL HEVC.mkv`
- 电视剧文件夹 `笑傲江湖 (2001) [tmdbid=…]/Season 01/`，文件 `笑傲江湖 (2001) - S01E05 - 1080p.mkv`
- 模板可用变量：`{title}` `{year}` `{tmdb}` `{season}` `{season2}` `{ep}` `{ep2}` `{res}` `{source}` `{codec}`；取不到的变量自动省略，不留空括号和多余的 -
- 分辨率、片源、编码从下载下来的文件名里取，取不到就用资源标题里的

## 只处理新增文件所在的目录（LitePan 联动按分类触发）
- 本服务入库后，会按**分类**给 LitePan 发通知，`联动来源` 里可以写 `{category}`，例如 `Emby求片-{category}` → 来源就是 `Emby求片-电影-国产`、`Emby求片-电视剧-国产剧`、`Emby求片-动漫` 等
- 在 LitePan 里**每个分类建一条联动**：触发 = 收到通知 `download_completed` + 对应来源；动作 = 刷新目录 → 执行 STRM 任务（该任务的扫描范围只选这个分类目录，如 影视/电影/国产）→（刮削）→ Emby 扫库（可只选对应媒体库）。这样新增一部国产电影，只会扫国产电影目录
- 设置页「联动来源清单」按钮会列出当前设置下全部来源，对照着建联动
- 不想分这么细：把来源写成固定值（不含 `{category}`），所有分类共用一条联动

## LitePan 按分类联动：具体怎么建
目标：新增一部国产电影，LitePan 只处理「影视/电影/国产」这一个目录，不碰别的分类。分三步：

**① 桥接站点（设置 → LitePan 联动）**：联动来源填 `Emby求片-{category}`，保存。点「联动来源清单」，会列出 11 个来源，以及每个来源对应的 STRM 任务该扫描的目录，例如：
`Emby求片-电影-国产 → 影视/电影/国产`、`Emby求片-电视剧-国产剧 → 影视/电视剧/国产剧`、`Emby求片-动漫 → 影视/动漫`

**② LitePan → 任务管理 → STRM 任务**：为每个分类建一个 STRM 任务，**扫描范围只选该分类目录**（如「影视/电影/国产」）。原来如果有一个扫描整个「影视」的任务，保留它做全量，但不要放进下面的联动里。

**③ LitePan → 任务管理 → 自动联动 → 新增联动**（每个分类一条，共 11 条）：
- 触发：第三方通知，名称 `download_completed`，来源填对应的来源（如 `Emby求片-电影-国产`）
- 动作按顺序：刷新目录 →（执行）STRM 任务：选这个分类自己的 STRM 任务 →（可选）刮削 → Emby/JF 扫库：选对应的 Emby 媒体库（别选「全局」）
- 保存并启用

效果与限制：
- 新增文件只会触发它所在分类的联动，只扫描该分类的目录，不会全盘扫描
- 但粒度是**整个分类目录**，不是单个文件：LitePan 的 STRM 任务按扫描范围工作，文档里没有「只处理某个新文件」的接口
- 「刷新目录」的作用是清除目录缓存，让 LitePan 重新读到网盘上的新文件，不会扩大 STRM 的扫描范围；如果发现新增文件没被扫到，就保留它
- 懒得建 11 条：把来源写成固定值（不含 `{category}`），所有分类共用一条联动，但那样 STRM 任务的范围就得是整个影视目录

## 对接 LitePan（直接触发它的自动联动）
文件进入正式目录后，本服务会调用 LitePan 的第三方通知接口，让它的联动完成 **整理 → STRM → 元数据 → Emby 刷库**，本服务自己不再刷 Emby。

在 LitePan 里准备：
1. 系统设置 → API 秘钥：新建一个**「任务执行」型**普通秘钥（`lpk_api_` 开头，创建后立刻复制，之后看不到）。STRM 媒体访问 Key 和只读 Key 不能用
2. 系统设置里配好 Emby 地址和 Emby API Key（联动里的「Emby 刷库」要用）
3. 任务管理 → 自动联动 → 新增联动：
   - 触发：**第三方通知**，通知名称填 `download_completed`，来源填 `RequestBridge`（或留空不限来源）
   - 动作按顺序：刷新目录 → 整理（源目录选本服务的「电影目录」「剧集目录」，目标路径要落在 STRM 扫描路径下）→ STRM → （可选）生成本地元数据 → Emby 刷库
   - 整理和 STRM 必须同一个网盘账号；联动里的整理没有人工预览，上线前先在「目录整理」页手动预览跑通
4. 回到本站「设置 → LitePan 联动」填地址（如 `http://192.168.1.10:5211`）、秘钥、通知名称、来源，点「测试 LitePan」

设置页的「测试 LitePan」和「手动触发联动」会把**实际发出的请求**（地址、JSON）、LitePan 的返回和一条可复制的 curl 命令都显示出来，对着 LitePan 联动弹窗里的「调用方式」核对；失败时会按情况给出提示（连不上 / 秘钥类型不对 / 接口 404 / 已接收但联动没执行）。

联动没有执行时，按顺序查：
1. **来源要一致**：LitePan 联动里「通知来源」填了什么（比如 `Emby求片`），本站「设置 → LitePan 联动 → 联动来源」就要填一模一样；对不上，LitePan 会收下通知但不触发联动。不想对来源，就把 LitePan 里的来源留空，本站也留空
2. **通知名称一致**：两边都是 `download_completed`
3. 看请求日志里的 LitePan 那一行：「已通知 LitePan（事件…，来源…）」说明发出去了、2xx 返回；「通知 LitePan 失败」会写原因（秘钥类型不对、连不上等）；如果日志里只有「已通知 Emby 刷新」，说明本站没配 LitePan 地址/秘钥
4. 请求本身要先成功（状态「已完成」）才会发通知
5. 设置页的「手动触发联动」会立刻发一条真实通知（不用等下载），用来单独验证联动配置；LitePan 里联动要已保存且处于启用状态

行为说明：
- 多个请求在「合并等待」（默认 20 秒）内陆续落盘，只会发一次通知，避免整理到没落完的文件
- 请求状态在文件进入正式目录、通知排队后就记为「已完成」；整理/STRM 是 LitePan 异步做的，结果看 LitePan 的任务日志
- 整理失败的话，LitePan 默认不会继续跑后面的 STRM 和刷库
- 不配 LitePan 也能用：文件落盘后等「未联动时等待」的秒数，由本服务通知 Emby 刷新

## 选源规则（.env 可调）
- 只要视频文件，nfo/海报/字幕/样片等下载后自动删除
- 标题明确写了低于 720p 的丢弃；没写分辨率的不丢，靠体积兜底，排序靠后；CAM/TS/枪版丢弃；**带水印的丢弃**（标题含「水印」「watermark」「带logo」等，「无水印」加分）
- 硬性范围：单个视频 500MB–5GB（`MIN_FILE_GB`/`MAX_FILE_GB`）
- 排序偏好：**1080p 最优先**（2160p、720p 靠后）；单文件/每集在 **1–3GB**（`PREFER_MIN_GB`/`PREFER_MAX_GB`）内加分；再看片源、中字、做种数，115 分享略加分
- 电影的分享里有多个版本时只保留一个（优先 1080p、落在 1–3GB 内的）
- 任何一步失败自动换下一个候选（最多 MAX_ATTEMPTS 个）；每次先下载到暂存目录，合格后才移入正式目录
